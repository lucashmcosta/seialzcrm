## P0 — corrigir esta semana

### 1. Auditoria DUPLICADA em contacts, opportunities e tasks
**Evidência:** cada tabela tem 3 triggers granulares (`audit_X_insert/update/delete`) + 1 combinada (`X_audit_trigger`, INS/DEL/UPD), todas → `audit_log_trigger`. Cada operação grava em `audit_logs` **duas vezes**.
**Impacto:** `audit_logs` = 292K linhas / **463 MB** (maior objeto do banco); write amplification no hot path; ~50% da tabela é lixo duplicado.
**Fix:** dropar as 3 granulares de cada tabela (manter a combinada), via migration. Depois avaliar expurgo dos duplicados históricos e retenção (particionar ou job de cleanup).
**Status:** [ ] pendente

### 2. Functions deployadas FORA do repo
**Evidência:** `twilio-message-debug`, `meta-capi-raw-test`, `marketing-campaign-enrich` têm entrypoint `source/index.ts` (deploy ad-hoc via dashboard) em vez de `source/supabase/functions/...` (deploy via repo), versão parada.
**Impacto crítico:** `marketing-campaign-enrich` é chamada por **cron a cada 6h e por trigger** (`fn_marketing_campaign_enrich_async`) — código de produção sem versionamento.
**Fix:** baixar o código deployado, commitar no repo em `supabase/functions/`, redeployar via pipeline. `twilio-message-debug` e `meta-capi-raw-test`: avaliar exclusão (parecem debug).
**Status:** [ ] pendente

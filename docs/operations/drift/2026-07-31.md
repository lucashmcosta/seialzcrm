# Drift 2026-07-31 — Recorrência de stale chunk (`Failed to fetch dynamically imported module`)

## Evento

Sentry reabriu `TypeError: Failed to fetch dynamically imported module: https://crm.seialz.com/assets/ContactsList-CHBn6tpk.js`
(ErrorBoundary raiz, via `ProtectedRoute` → `Suspense`).

## Achados (read-only, antes do ajuste)

- `isStaleChunkError` (`src/App.tsx`) já cobria a mensagem; `retryImport` já suspendia e chamava `reloadForChunkRecovery()`.
- `reloadForChunkRecovery()` fazia `window.location.reload()` **sem cache-busting** e desistia (`false`) dentro da janela de 10s.
  Se o reload devolvesse o mesmo `index.html` cacheado, a segunda falha vazava para o ErrorBoundary → evento no Sentry.
- `vercel.json` não declarava `Cache-Control` para o HTML (`/` e `/index.html`).
- O filtro do `beforeSend` no Sentry não cobria as variantes `_result.default` / `reading 'default'`.

`[INCERTO]` A causa única do evento não pode ser confirmada sem o `release` associado no Sentry; parte dos eventos
pode ser cauda de abas rodando builds anteriores às mitigações.

## Ajustes aplicados

1. `src/App.tsx` — `reloadForChunkRecovery()` passa a escalonar: 1ª tentativa por sessão = reload simples;
   tentativas seguintes = `hardRefreshApp()` (unregister de SW, flush de `caches`, URL com `?app-refresh=`).
   Contador em `sessionStorage` (`__seialz_chunk_recovery_attempts`).
2. `vercel.json` — `Cache-Control: public, max-age=0, must-revalidate` para `/` e `/index.html`;
   `/assets/*` continua `immutable`. Rewrite SPA inalterado (deep links preservados).
3. `src/instrument.ts` — `STALE_CHUNK_PATTERNS` alinhado com `isStaleChunkError`.

## Verificação

- `bun run build` verde.
- Pós-deploy: conferir se novos eventos dessa issue carregam o `release` atual. Se permanecerem em release antigo,
  é cauda de abas velhas e a issue pode ser resolvida no Sentry.
